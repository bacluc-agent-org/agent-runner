Progress reporting (mandatory in every run of this issue, including by subagents):
The runner ensures one canonical progress comment before the coordinator starts. Use only the newest issue comment authored by the authenticated user whose body contains the HTML marker <!-- agent-progress -->; never select or edit another user's marker. Find the authenticated login with gh api user --jq .login and list comments with gh api --paginate repos/<owner>/<repo>/issues/<number>/comments. Edit that comment in place with gh api -X PATCH repos/<owner>/<repo>/issues/comments/<id> -F body=@<file>. Use -F, never -f: -f is --raw-field and would send the literal text @<file> and wipe the comment. Never create another marked or unmarked progress or status comment, including per run, per step, per milestone, or by a subagent; the runner adds the run rows itself. If the canonical comment is missing, do not create one: the runner handles it.
Fill these sections and keep the headings, each verbatim with three hashes at level three: "### Management summary" (2-3 sentences for a human, no tool output), "### Design decisions" (the decisions that shaped the change, and why), "### Open PR" (the pull request of this run; write "none - this run pushed no pull request"), "### Verification evidence" (absolute action-run links with job/step anchors, per AGENTS.md; never cite the automatic ci.yml or ./scripts/completion-check as your own testing), "### Action runs" (one row per run: Run | Model | What happened | Result | Failure reason). A heading at another level makes that step lose this run's result row, and the job still reports success.
Add run history ONLY as rows of the Action runs table, keyed by the run URL; never a heading or prose block per run.
Put durable context for later runs inside the collapsible <details> block; keep it short.
Post a separate comment ONLY as a short reply to a human comment: quote the human comment and add one acknowledgement line. Never the run report.
Pass these rules verbatim into every subagent prompt.
Pull request body: a description of the change that opens with the absolute link to the issue, then Management summary, then Verification evidence, then the same five-column Action runs table.

At the end of your final run output, write exactly one line beginning AGENT_OUTCOME: followed by a JSON object with fields status, kind, summary and url. Use status "completed" only after delivery, otherwise "blocked" or "incomplete". For code, kind is "code" and url is the absolute URL of an open pull request containing changes; its body must link this run URL and the target issue when present. For no-code work, kind is "report", url is empty, and summary is a substantive, specific account of findings. If there is a target issue, put that exact summary and this run's absolute URL in the canonical progress comment's Management summary section. A pushed branch alone is not delivery. Do not write the outcome line until the work is finished.
